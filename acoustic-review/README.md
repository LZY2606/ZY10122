# Pair-wise Acoustic Review Workbench

离线声学事件审查工具。采集器只上传短时特征（本地时钙/起峰时刻、峰值频带、
SNR、若干互相关延迟），工程师在浏览器中建立事件、比较声源位置候选、区分
直达与反射证据，并把人工判断作为**派生证据**追加保存。

## 组成

- `src/` Rust 服务（HTTP API + SQLite + 确定性 TDOA 求解器）
- `static/` 浏览器单页：空间视图（站点、延迟关联、交会区/双曲轨迹、候选）
  与站点时线视图（缺席/重复上报、半开区间）
- `src/synth.rs` 合成数据生成器（确定性 PRNG，三个演示场景）
- `tests/` 时钟半开边界、欠定几何、批次幂等、崩溃恢复、并行排名稳定性

## 安装与演示

```sh
cargo fetch --locked
cargo test --locked
cargo run --locked -- --listen 127.0.0.1:5322
# 打开 http://127.0.0.1:5322
```

首次启动（且数据库为空）会自动生成合成站点、时钟分段、批次并完成三次求解。
`--db <path>` 指定数据库文件，`--no-seed` 关闭自动播种。

## 单位

所有距离为米（`m`），时间为秒（`s`），延迟为秒（`s`），声速为米每秒
（`m/s`，默认 343）。API 的每个事件都重复声明这些单位
（`coordinate_unit`、`time_unit`、`delay_unit`、`speed_unit`）。
`observable_radius_m`（默认 2000 m）定义可观测几何域：落在域外的数值估计
会被**丢弃**，不会被优化器硬拉回边界——这类输入以 `circle` 空区域 + 原因
说明返回。

## 时钟模型：分段偏移与半开边界

每台采集器拥有若干**互不重叠的半开**时钟校正段：

```
[start_s, end_s)      offset_s = 加在设备时钟上的校正量（秒）
[start_s, NULL)       末段开放到无穷远
```

- 半开语义：两个恰好相接的段 `[0,60)` 与 `[60,+∞)` 在 `t=60` 时**只有后者**
  生效；写入重叠区间会被拒绝（见 `tests/clock_boundaries.rs`）。
- 事件中点 `t_mid` 落在哪个段，就用该段 `offset_s/sigma_s` 对相关延迟做
  差分校正。
- 没有任何段覆盖该时刻时，该站被视为**自由时钟**（σ=1 s 的结构自由度）。
- 工程师可以用 `lock_clock` 证据锁定一个校正段/校正量；锁定优先于预置段，
  并参与下一次求解指纹。

## 定位与欠定结果

求解输入是去重、时钟差分校正后的成对延迟边（互相关 `xcorr` 与起峰差
`onset` 两类来源都会标注）。星型参考站解析方程 `(p_i-p_0)·x + d·r0 =
(K_i-K_0-d²)/2` 给出闭式解，再以 Gauss-Newton 在全部边上精化：

- 3 个几何独立时差 → `point` / `determined`。
- 仅 2 个独立时差（如三站共线）→ 沿零空间代入二次约束，通常得到**两个镜像
  点**，标记为 `point` / `underdetermined`，原因 `sensor_geometry`；工程师可
  用 `keep_pair` 证据把两者作为不可分位置同时保留。
- 仅 1 条有效边 → `region`（`hyperbola` 分支形状 + 不确定宽度）。
- 参与站存在未覆盖时钟段且时差被时钟不确定度主导 → `region`（`line`），
  原因 `clock_freedom`。
- 测量延迟超出基线（双曲线不存在）或闭式解落到可观测域外 → `circle` 空区域，
  说明几何上无可行位置。
- 全部“直达”边统计上不自洽（加权 RMS 超阈值），但剔除某条疑似多径边后自洽
  → 该点标记为 `underdetermined`，原因 `multipath`：直达与反射证据尚未由工程
  师区分；追加 `exclude_peak` 证据后重算即可确认。

每个候选都带**残差分解**：逐边给出实测/预测延迟、残差、σ、nσ，并标注
`xcorr/onset`、多径与是否被排除。疑似多径边（上传时 `multipath=true`）默认
作为待区分证据参与，求解器枚举有限数量的“疑似边剔除”分支并合并去重；
工程师可对任意可疑路径（包括伪装成直达峰 `peak_index=0` 的反射）追加
`exclude_peak` 证据将其判定为反射，下一次作业再计算残差。

## 派生证据、批次指纹与排名稳定性

- 观测与历史候选**永不修改**。审查动作（排除反射路径、锁定时钟段、保留两个
  候选）只追加到 `evidence` 表，内容 ID 是 `(event, kind, canonical JSON)`
  的 SHA-256，因此同一决策重复提交是幂等的，证据编号在并行/重复求解间稳定。
- 上传批次以**批次指纹**为主键。崩溃后重放同一指纹不会再次插入观测
  （`tests/persistence.rs`）。
- 每次求解有**作业指纹**（规范化 JSON 覆盖站点、段、边、声速、锁定/排除/
  保留对）。相同输入命中同一作业；候选只属于 `state='done'` 的作业，未完成
  作业的候选不会出现在审查接口。
- 候选按 `(RMS nσ, 最大残差, x, y)` 的确定性顺序排名，`cand_key` 由事件 ID
  与量化坐标/区域内容哈希得到。固定输入下并行求解给出完全相同的排名与编号
  （`tests/parallel.rs`）。

## 崩溃恢复

启动时与 `POST /api/recover` 会：

1. 把停留在 `running` 的作业重置为 `created`；
2. 删除这些作业的半成品候选（它们从未成为可审核结果）；
3. 批次主键保证重放不重复添加观测；随后重新求解即生成完整候选集。

## HTTP API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/stations` / `POST /api/stations` | 站点（坐标 m） |
| POST | `/api/clock-segments` | 新增半开时钟段（重叠拒绝） |
| GET | `/api/events` / `POST /api/events` | 事件（半开区间） |
| POST | `/api/batches` | 上传/重放特征批次（指纹幂等） |
| POST | `/api/events/{id}/link` | 按事件引用/半开时窗关联观测 |
| GET | `/api/events/{id}` | 时线、边、证据、作业、候选与残差 |
| POST | `/api/events/{id}/evidence` | 追加派生证据 |
| POST | `/api/events/{id}/solve` | 基于当前证据重算（新作业） |
| POST | `/api/recover` | 崩溃恢复 |
